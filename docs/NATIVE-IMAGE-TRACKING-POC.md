# 本尊鸿蒙原生 AR 原型

更新日期：2026-10-27。开发分支：codex/harmony-kivicube。

2026-10-27 已完成取帧、识别调度、时域稳定、WebGL 纹理更新和音频定时器的专项优化，离线精度及稳定性回归通过。首次将帧调整为 `small` 后真机反馈实际 AR 画布不清晰，现已恢复 `medium` 显示帧，同时在内部直接降采样为独立识别尺度，鸿蒙真机清晰度与流畅度仍待复测。详细变更与验收方法见 [鸿蒙原生 AR 流畅度与稳定性优化](NATIVE-AR-PERFORMANCE-2026-10-27.md)。

## 当前结论

用户已在鸿蒙微信预览版确认原生相机实时画面、RGBA 有效帧计数持续增长，以及 WebGL 绿色画布显示。确认的是基础能力，不是完整 AR。

当前路线：camera 帧 → 本地 ORB 首次识别/LK 连续追踪 → 单应矩阵几何验证 → 姿态估算 → WebGL 墨玉模型及动画特效，配合原生讲解/环境音。没有使用 VisionKit、收费 SDK、远端识别或宿主 web-view。

用户已在鸿蒙真机确认绿框定位、移动倾斜和重新识别。优化后用户截图进一步证实墨玉 3D 模型已显示：连续追踪 65 ms、预览和定位约 9.6 次/秒、页面记录绘制 2 ms、姿态拟合误差 17.5 px。绘制数值是调用耗时，不是 GPU 完整耗时，也不能代表所有机型性能；尚需校准贴合和完整丢失恢复。用户要求接入特效与音频，本轮已完成盾、山、法阵、文字及讲解/环境音代码接入，新增内容等待真机验证，最终鸿蒙 AR 兼容问题尚未完成验收。

## 真机操作

1. 使用本分支最新工程重新编译，生成开发版预览或体验版。
2. 在目标鸿蒙微信进入模型选择页，点击“本尊原生图片追踪”。该入口只在开发版/体验版显示。
3. 在电脑或另一台设备打开 recovery-assets/cards/tssgd.jpg，保持原图宽高比，不只显示截图中的局部。
4. 页面会从原工程资源地址下载约 8.7 MB 墨玉模型，再依次加载约 2.7 MB 的盾、山、法阵、文字特效。等待主模型与特效均显示“已就绪”。失败可分别重试；单个特效失败不影响主模型与其他成功的特效。下载遵循小程序 downloadFile 合法域名规则，未关闭校验。
5. 点击“开始图片追踪”并允许相机。上方是原生相机预览，下方是算法处理并叠加模型的实际取帧画面；本轮仍是开发验证界面。
6. 先正对识别图并让图占较大画面，再轻微倾斜和移动。检查下方完整卡片绿框贴合，模型正面是否朝向正确，倾斜时模型是否有立体透视且跟随卡片。模型初始大小参照识别图中印刷形象设置，可用下方“模型大小”“上下位置”“相机视角校准”调整。
7. 连续识别至少 5～10 秒，确认盾旋转、山出场/缩放、法阵展开/旋转和金色文字。原素材中山在约 2.3 秒后开始出场，法阵初始很小；盾约 10 秒循环，山和法阵约 37.5 秒循环，不应把最初短暂未出现判作加载失败。
8. 识别后环境音循环、讲解播放一遍。移开识别图应隐藏模型与边框、暂停特效时间与声音，重新移入继续；讲解播完不自动重播，可点“重新播放讲解”。停止追踪/后台/退出页面会停止声音，重新开始一轮会重置动画和讲解。
9. 分别用“仅绿框”“关闭特效”“关闭声音”对比流畅度。帧率不能仅凭匹配数量判断，必须看到正确的定位与模型贴合。
10. 截图反馈模型/特效/音频状态、方向/位置、绘制耗时、姿态拟合误差、处理模式和实际预览帧率/定位频率。分别记录“完整识别”和“连续追踪”，不能用连续追踪的一帧耗时代表完整识别的耗时。记录手机型号、HarmonyOS 和微信版本，以区分机型差异。

画面仅在设备内处理，不保存、不上传。停止、离开页面和进入后台均释放取帧监听，防止旧会话回调污染新会话。

## 离线验证

使用本尊原图经独立变换构造 480×640 测试画面：缩放平移、15°旋转、90°旋转、透视、非目标帧后重新识别；校验投影四角与已知真值的最大误差小于 10 像素。最后一次本机运行各正例误差约 1.03～3.21 像素。

负例覆盖空白、确定性噪声、一张工程内无关图片，以及错误长度帧。没有将这些少量测试外推为所有场景的误识别率。检测耗时是在本机 Node 环境测得，不能作为鸿蒙手机帧率承诺。

几何估计采用固定工作上限、根据匹配数据初始化的本地采样序列以及局部重估，避免通用随机估计器在该卡片上因退化点组提前退出；相同输入的结果可复现。图像处理复用角点缓冲，并限制检测分辨率及处理频率，实际手机性能待测。

图片特征、识别库、姿态计算、GLB 和动画读取代码随测试分包本地加载。主模型/特效/音频均在运行时读取原工程资源地址，未加入代码包；最终体积以微信打包报告为准。

### 本轮特效与音频接入（真机待验证）

- `effects-config.js` 保存原工程素材地址与布局：dun.glb、shan.glb、dcdy02.glb、sgd.glb，保留原相对缩放/位置，通过主模型归一化矩阵统一映射到当前卡片坐标；大小、上下位置和视角校准同时作用于整个场景。不同识别引擎下仍需真机确认布局。
- 4 个文件当前均 HTTP 200，总计 2,721,552 字节；环境音 874,420 字节，讲解 363,102 字节，均 HTTP 200。首次完整场景累计读取约 12.65 MB（包含主模型），不新增服务器。
- 扩展 GLB 读取为内嵌纹理、OPAQUE/BLEND 和节点 TRS 动画；`animation.js` 保留原始关键帧，向量 LINEAR/STEP 插值、旋转采用最短路径四元数球面插值，按原片段时长循环。现有素材共有 11 条动画通道；文字本身无动画。未实现骨骼、变形、压缩扩展和 CUBICSPLINE，遇到未支持输入会显式拒绝。
- 原有墨玉 5 网格保持不透明深度写入；加上文字不透明网格、6 个透明特效网格，总计 12 次网格绘制。透明部分按相机深度从远到近绘制、关闭深度写入、使用标准 alpha 混合，保留原贴图透明通道。对这些非二次幂纹理用着色器保持 REPEAT UV，避免山素材的负 UV 被裁切。复杂透明面交叉仍需真机观察，不承诺完全复现原平台光照/发光。
- 动画仅在主模型可见时推进；目标丢失、仅绿框模式暂停，重新可见继续；停止追踪重置。特效独立加载、部分失败可重试，已经就绪的主模型不会因特效下载失败被销毁。
- `audio.js` 创建两个原生 InnerAudioContext：环境音循环、音量 0.3，讲解单次、音量 0.6。实际 3D 姿态通过并显示才播放，目标丢失或切到仅绿框暂停、重新显示继续；讲解结束后不自动重播，按钮可重播。播放错误可见，关闭再开启声音可重试，不会每帧重复调用 play。500 ms 内没有刷新可见状态会暂停声音，避免取帧中断后继续响；停止/后台重置，卸载销毁两个音频对象。
- 离线检查覆盖真实 4 份特效读取、原始节点被关键帧替换、旋转/缩放变化和循环、四元数短路径、暂停恢复、GPU 动画矩阵、透明/不透明深度状态、部分失败、下载/文件/GPU 释放，以及页面实际可见性与音频联动。GPU 模拟不等于真实着色器/透明效果验证；音频状态模拟不等于鸿蒙实际播放验证。
- 动画插值与透明合成依据 [Khronos glTF 2.0 规范](https://registry.khronos.org/glTF/specs/2.0/glTF-2.0.html#animations)。没有引入新的收费 SDK 或浏览器引擎。

### 墨玉 3D 接入（用户截图已证明显示，仍待完整交互验收）

- `model-config.js` 使用原工程 `AR-YSJ/Model/taishanshigandang_yu.glb` 地址，当前 HTTP HEAD 为 200，长度 8,688,904 字节。不要求新增服务器，未更改现有 Android/iOS 正式业务路由。
- `glb.js` 读取现有 GLB 2 的节点层级、静态三角形网格、法线、UV 和内嵌基础色贴图，主模型烘焙节点变换并以卡片高度为单位归一化。原模型有 5 个网格、103,575 个三角形及 5 张使用中的基础色贴图；实际索引转为 Uint16，不要求 uint32 索引扩展。不是完整的通用 glTF 引擎，新增的动画/透明支持范围见本轮记录。
- `pose.js` 从卡片四角计算平面单应矩阵，用估计相机内参分解刚体姿态，正交化旋转后绘制真正的 3D 网格。相机图像坐标为右/下/前，卡片高度为 1；模型正面与印刷形象方向对齐，模型厚度向相机方向伸出卡片。相机与模型共用同一张取帧画布，避免额外的原生相机裁剪映射误差。
- 相机垂直视角默认 50°，为估算值，未取得真机标定内参。提供 30～80° 视角、50～150% 模型大小和上下位置调节。严重不一致的姿态会被隐藏并显示校准提示，不能把绿框精度直接当作 3D 姿态精度。
- `model-renderer.js` 主模型采用基础色贴图和简单环境/方向光，特效使用不受灯光压暗的贴图颜色；保留深度测试。未恢复原材质的金属度/粗糙度、法线贴图和环境反射，外观不保证与旧 XR-Frame/共创 AR 完全一致。
- 模型加载进度、失败重试、仅绿框切换、绘制耗时和姿态拟合误差可见。模型失败不阻止原有相机/绿框测试。卸载中断未完成下载并释放 GPU 资源，临时贴图文件使用本轮独有文件名、上传后删除，晚到回调不再操作已关闭页面。
- 离线验证包括真实 GLB 的 5 网格/5 贴图及归一化、损坏文件拒绝、正面/倾斜/90°方向及离平面 3D 点投影、模型隐藏和 GPU/文件/下载生命周期。独立合成相机投影的离平面误差小于 0.02 px；这只是已知内参条件下的数学检查，不是手机精度承诺。软件参考渲染检查模型正面方向与贴图，随后用户截图已证明基础模型在鸿蒙显示。新增特效着色器、混合及音频仍待真机复测。

### 流畅度优化（用户模型截图记录约 9.6 帧/秒）

- 旧版每帧完整识别，再等待至少 250 ms，且只在完整识别后更新预览。188 ms 的识别计算加等待已是至少 438 ms 一轮，尚不含绘制等开销。
- 新增 session-tracker.js：完整 ORB 识别后保留已验证的特征对应关系。清晰度修正后相机和 WebGL 显示使用 `medium` 原帧，稳定追踪直接生成长边最多 400 像素的灰度图，并以最多 48 点的三级金字塔 LK 光流执行前后向一致性、亮度变化容忍的局部贴片比较和单应矩阵验证；完整识别仍使用最长边 480 像素的高质量灰度缩放。
- 连续追踪对照最近一次完整识别的关键帧，避免逐帧累积漂移。稳定状态最多约 5 秒重新进行一次完整识别；画面变化太大、目标丢失、回调间隔超过 500 ms、相机尺寸改变以及停止重启都会丢弃旧追踪。一次短暂失败由稳定器短时保持，持续丢失后清除边框并重新识别。
- 连续定位按实际耗时背压，最快约 66 ms 一次；未定位时完整识别至少间隔约 280 ms。预览独立按实际绘制耗时调度，最快约 40 ms 刷新。稳定器对一次短暂失败最多保持约 170 ms，跳过定位计算的预览最多沿用约 220 ms 内的稳定结果；状态文字更新节流至约 750 ms，模式/定位状态改变时立即更新。
- 页面显示最近约一秒的实际预览帧率及定位处理频率，均为实测计数，不是固定的帧率承诺。
- 清晰度修正后的合成会话测试共 40 个正例帧通过，其中 35 帧走连续追踪，最大四角误差约 8.07 像素（要求仍为小于 10 像素）。另覆盖目标消失、无关图、亮度变化、长间隔、停止重置及相机尺寸变化；页面模拟测试确认预览可在两次完整识别之间刷新、单帧失败短时保持、持续丢失后清除、停止后旧回调无效。

计算仍同步运行在小程序逻辑线程，完整识别和定期复核仍可能造成短暂停顿。预览与识别调度已拆开，但不等于算法已转到后台线程。PC 离线耗时不能证明鸿蒙实际帧率，也不能保证叠加 3D 后仍流畅。下一步对比“仅绿框”和“显示墨玉模型”，记录帧率及绘制耗时，再决定是否需要模型减面、工作线程等进一步优化。

## 重建与测试

需要 Pillow 的 Python 环境，运行 recovery-tools/prepare-native-target.py 生成临时的 640 像素上限 RGBA 参考图及尺寸 JSON。默认输出系统临时目录 ysj-native-target.rgba / ysj-native-target.json。

随后运行：

```text
node recovery-tools/train-native-target.cjs <参考图.rgba> <尺寸.json>
node recovery-tools/test-native-tracker.cjs <参考图.rgba> [480×640无关图片.rgba]
node recovery-tools/test-native-session.cjs <参考图.rgba> [480×640无关图片.rgba]
node recovery-tools/test-native-page.cjs
node recovery-tools/test-native-model.cjs
node recovery-tools/test-native-model-renderer.cjs
node recovery-tools/test-native-effects.cjs
node recovery-tools/test-native-audio.cjs
```

特征文件 pages/ar-native-track/target.js 已生成，可直接编译预览，无需用户手机执行训练。当前参考图尺寸 427×640，包含 602 个多尺度特征。

### 页面空白修复（2026-10-26）

用户反馈点击“本尊原生图片追踪”后页面空白。检查发现页面注册前直接 require("./target.json")，误用了 Node 的 JSON 模块加载能力。现改为 target.js 导出相同特征数据，同步修正训练脚本及离线测试引用；依赖初始化放在页面注册后的 onLoad 中捕获错误，画布查询同步异常也会显示在状态文字中。

新增 `node recovery-tools/test-native-page.cjs`，以仅加载 JS、不提供浏览器全局对象的模块环境验证页面注册、真实依赖加载及依赖失败时的可见错误。该检查能够复现旧代码在 Page 注册前中断的问题。修复后需清理开发者工具缓存并重新编译生成新的预览码，在鸿蒙真机复核；不能把离线启动测试当作真机通过。

工程检查还覆盖页面启动停止、旧监听回调隔离、后台释放及画布资源释放。JSON、JS、WXML、本地依赖和素材引用检查通过。
